# 麦麦急救包

**站在公司楼下，打开麦当劳 APP，翻半天菜单，算半天券，最后随便点一个，吃完觉得亏了。**

如果你点头了，这个就是给你做的。

说一句人话，它把菜单、热量、券、积分全替你过一遍，给你**最多三个方案，一个一行字**：吃什么、多少钱、用哪张券、大概多少卡。

然后它停下来问你一句：就这个？

## 它到底在解决什么

麦当劳的券规则比高数还绕。满减、立减、买一送一、限定单品、限定门店、限定渠道，还有"要用这张券得先加钱买麦金卡"这种操作。你在柜台前站着，前面还有三个人排队，这时候你不可能算得清楚。

更别提"我想减脂"这件事。APP 里你得点进每一个汉堡，一个个看详情，才能知道热量。看到第五个的时候你就放弃了。

这个 skill 把这两件事一起办了：**它替你算，而且算的东西全部来自麦当劳的实时数据，不是瞎编的。**

## 看看它长什么样

### 「中午想吃麦当劳，减脂，40 块以内，别给我推荐炸的」

```
中午这三个，都过了你的条件：

1. 双层吉士汉堡 · 23 元 · 没用券 · 约 429 大卡 · 蛋白质 27g
2. 板烧鸡腿堡 · 24 元 · 用「板烧立减3元」· 约 391 大卡 · 蛋白质 23g
3. 不素之霸双层牛堡 · 26.5 元 · 没用券 · 约 493 大卡 · 蛋白质 28g

按你说的把 8 个油炸的踢了（麦辣鸡腿汉堡、麦辣鸡翅这些）。
另外 21 个餐品麦当劳的营养表里查不到数据，我没敢给你算热量，也排除了。

要哪个？
```

注意最后那句"要哪个"。**它不会自己下单。**

### 「我有啥券快过期了」

```
3 张券撑不住了：

· 巨无霸三件套立减5元 —— 还剩 3 天，这周内安排掉。能买：巨无霸三件套
· 中薯条免费券 —— 明天最后一天。能买：中薯条
· 全场满30减6 —— 还剩 20 天，不急

另外「圆筒冰淇淋买一送一」已经过期了，别惦记了。
```

"每张券还能买什么"这件事，很多工具是查不出来的——它得真去查这张券限定的商品编码，再跟门店当前菜单对。这个 skill 查了。

### 「我想试薯条蘸冰淇淋」

```
薯条蘸冰淇淋：
  薯条        14 元    289 大卡
  圆筒冰淇淋    5 元     93 大卡
  合计 19 元，约 382 大卡

怎么点：APP 里分开点一份中薯和一支圆筒，取餐了自己蘸。
热量提醒：382 大卡，差不多是一顿正餐的三分之一。
备注：菜单写「薯条」、营养表里只有「中薯条」，热量按中薯条算的。
```

最后那行备注是我特意留的。**只要它替你猜了，就得说出来。**

### 「我积分快过期了」

```
你可用积分 0 分。

最划算的换法：
· 6.9元可乐麦炫酷 —— 50 分，100 分能抵 13.8 元。你现在还差 50 分。

另外：你已经有 3704.6 分过期作废了，这个追不回来了。
说明：麦当劳只给了「本月/下月将过期」这个粒度，查不到精确到哪天，所以我只能说到月底。
```

余额是 0 就说 0，不给你硬凑一个"推荐"。查不到精确日期就说查不到——这比给你一个假日期强。

## 装起来

### 1. 拿一个麦当劳 MCP Token

去 <https://open.mcd.cn/mcp>，右上角登录（手机号验证），进「控制台」点「激活」，复制 Token。

### 2. 把 MCP 接进 WorkBuddy

左侧边栏「专家·技能·连接器」→【连接器】→ 右上角【自定义连接器】→【配置MCP】，粘贴：

```json
{
  "mcpServers": {
    "mcd-mcp": {
      "type": "streamablehttp",
      "url": "https://mcp.mcd.cn",
      "headers": {
        "Authorization": "Bearer ${MCD_MCP_TOKEN}"
      }
    }
  }
}
```

把 `${MCD_MCP_TOKEN}` 换成你自己的 Token（**只在本地改，别提交进 Git**）。如果你的客户端不支持环境变量替换，就直接粘真实 Token。

保存，然后回列表把 `mcd-mcp` **启用**。

> 仓库里的 `mcp-config.example.json` 和上面的片段都**只使用环境变量占位符**，不含任何真实凭证。`Authorization` 的值永远不该出现在提交历史里。

### 3. 把 skill 放进去

```bash
git clone https://github.com/<你的用户名>/mcd-first-aid-kit
cp -r mcd-first-aid-kit ~/.workbuddy/skills/maimai-first-aid
```

（Windows 上是 `%USERPROFILE%\.workbuddy\skills\`）

然后直接跟它说话就行。

## 没 Token 也想先看看？

可以。仓库自带真实抓包的测试数据：

```bash
npm run demo
```

它不连 MCP，用仓库里 `test/fixtures/` 的真实数据跑一遍上面那四个场景。**先看效果，再决定要不要配 Token。**

我自己的习惯是先看效果——毕竟配 Token 这一步挺烦的。

## 谁用得上

- **每天中午要选一次的上班族**。省下的不是钱，是那种"又随便点了一个"的憋屈感。
- **在减脂、但不想彻底告别麦当劳的人**。热量数据摆在这儿，你自己决定今天要不要吃巨无霸。
- **卡包里躺着一堆快过期券的人**。这些券过期的时候是不会提醒你的。
- **想省钱但懒得研究券规则的人**。让它算，它不怕烦。

## 它是怎么算的

核心逻辑没写在提示词里，而是写成了**带测试的纯函数**（`src/core/`）。原因很实在：靠语言模型现场心算热量和比价，一定会飘。所以：

- `nutrition.js` —— 菜单名和营养表名的匹配（这俩叫法不一样，是整个项目最麻烦的地方）
- `coupon.js` —— 券的有效期解析、临期分桶、适用商品校验
- `plan.js` —— 候选筛选、组合生成、方案排序
- `points.js` —— 积分商城性价比排序

**决策本地算，价格绝不本地算。** 券规则、麦金卡、随单购、特调加价，本地复刻一遍必然算错——所以所有金额一律以麦当劳 `calculate-price` 的返回为准，本地估算只用来排序。

调了哪些 MCP 工具、什么顺序、为什么非它不可，都写在 [`MCP_INTEGRATION.md`](./MCP_INTEGRATION.md) 里。

## 它不乱来

- **不自动下单。** 下单前一定停下来问你，拿到明确答复才动。
- **不编数据。** 热量、价格、积分、有效期，全部来自本次真实调用。
- **不硬推。** 券和菜对不上就直接说对不上。查不到营养数据就说查不到。
- **不占便宜。** 它不篡改任何请求，不绕过门店和渠道校验，就是老老实实调官方 MCP。

## 说点实话

这个 skill 的每一个"坑"，都是我配 Token、调工具、被数据打脸之后才知道的。比如：

- 营养表里根本没有商品编码，只有菜名，而菜单上叫「薯条」、营养表里叫「中薯条」
- 积分接口只给"本月/下月将过期"，没有精确日期
- 积分商城的 `price` 字段不是商品价值，是"除积分外还要另付多少钱"

这些不是我想出来的边界情况，是真跑出来的。所以我把它们写进了代码注释、写进了 `MCP_INTEGRATION.md`，也写成了测试用例。下次有人改这个项目，不会再把同一个坑踩一遍。

**这个功能我自己每天都在用。** 中午那句"减脂、40 以内、别推荐炸的"，现在是我一天里最省事的一句话。
